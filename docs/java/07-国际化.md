# i18n 使用

> 更新日期：2026-08-19 · 适用版本：WalnutSeed v1.0

后端消息的国际化（i18n）按请求头 `Accept-Language` 自动生效，支持 `zh_CN` / `en_US`。本文讲清机制、如何新增消息，以及**当前的接入边界**（哪些消息已国际化、哪些仍是硬编码）。

## 1. 机制

这是一套**自研的轻量实现**（基于 `ContextVar` + `.properties` 文件，不用 gettext/babel），核心在 `app/utils/i18n.py`。

### 1.1 语言是如何被选中的

```
前端 axios 拦截器注入 Accept-Language（zh_CN / en_US）
        │
        ▼
LocaleMiddleware（纯 ASGI）→ _resolve_locale() 解析请求头 → set_locale() 写入 ContextVar
        │
        ▼
业务代码 / 异常处理器调 MessageUtils.message(key) → 按当前 ContextVar 读取对应语言
        │
        ▼
请求结束 finally → reset_locale() 还原，避免请求间串用
```

请求头解析规则（`app/core/middlewares.py` 的 `_resolve_locale`）：

```python
raw = headers.get("Accept-Language") or headers.get("Content-Language") or ""
primary = raw.split(",")[0].split(";")[0].strip().replace("-", "_")  # 只看第一个语言项，剥 q 值
prefix = primary.split("_")[0].lower()
if prefix == "zh": return "zh_CN"
if prefix == "en": return "en_US"
return "zh_CN"     # 其余语言一律回退默认
```

要点：**只看第一个语言项、按语言前缀归一化**（`zh-TW`→`zh_CN`、`en-GB`→`en_US`），不解析 q 权重排序；未知语言一律回退 `zh_CN`。

### 1.2 LocaleMiddleware 为什么是纯 ASGI

`LocaleMiddleware` 刻意**不继承 `BaseHTTPMiddleware`**——后者会把下游处理放进独立的 anyio 任务，中间件里 set 的 `ContextVar` 对下游不可见。纯 ASGI 实现保证语言上下文与路由/异常处理器在**同一任务**内可读，请求结束在 `finally` 里 `reset_locale`：

```python
async def __call__(self, scope, receive, send) -> None:
    if scope["type"] != "http":
        await self.app(scope, receive, send); return
    token = set_locale(_resolve_locale(Headers(scope=scope)))
    try:
        await self.app(scope, receive, send)
    finally:
        reset_locale(token)
```

它在中间件链里位于 CORS 之内、所有业务中间件之外（顺序见 `app/config/setting.py` 的 `MIDDLEWARE_LIST`），保证后续任何中间件/路由抛异常时翻译语言都已就位。

### 1.3 翻译查找与回退

唯一对外入口是 `MessageUtils.message(code, *args)`：

```python
# 三级回退合并：精确 locale → 语言前缀 → 默认 zh_CN（精确匹配优先级最高）
candidates = [locale, locale.split("_")[0], "zh_CN"]

template = _messages_for(get_locale()).get(code)
if template is None:
    return code                      # ⭐ 找不到翻译时原样返回 key 本身（不报错）
if args:
    return template.format(*args)    # {0}/{1} 位置占位符
```

行为约定：

- **未命中的 key 原样返回**（异常基类据此判断"未命中"并回退默认消息，见 2.2）；
- 资源文件首次访问该语言时加载一次，之后走进程级内存缓存——**改 `.properties` 需重启进程**才生效；
- 占位符格式化失败（参数个数不符）会回退返回原模板。

## 2. 新增一条国际化消息

### 2.1 登记消息文件

消息文件是 **Java 风格 `.properties`**（不是 .po / .json），位于 `app/i18n/`：

- `messages_zh_CN.properties`
- `messages_en_US.properties`

两份文件逐条对齐，格式 `key=value`，`#` 开头注释，`# ===== 分组名 =====` 分段：

```properties
# messages_zh_CN.properties
# ===== 登录重试 =====
user.password.retry.limit.exceed=密码输入错误{0}次，帐户锁定{1}分钟

# messages_en_US.properties
user.password.retry.limit.exceed=Password entered incorrectly {0} times, account locked for {1} minutes
```

**key 命名约定**：全小写、点分层级，领域前缀打头——`user.*`（登录/注册/密码/验证码）、`auth.*`（客户端/授权类型）、权限类 `not.permission` / `not.login` / `not.role`、设施类 `repeat.submit.message` / `rate.limiter.message` / `upload.exceed.maxSize`。新增消息请沿用同一前缀体系，并在**两个语言文件里同时登记**。

占位符用 `{0}` / `{1}` 位置参数（Python `str.format` 填充）。

### 2.2 在代码里使用

核心入口 `MessageUtils.message`：

```python
from app.utils.i18n import MessageUtils

msg = MessageUtils.message("user.password.retry.limit.exceed", 3, 10)
# zh_CN → "密码输入错误3次，帐户锁定10分钟"
# en_US → "Password entered incorrectly 3 times, account locked for 10 minutes"
```

**抛业务异常时优先走 i18n**。`ServiceException` 支持三种用法，推荐第 ②③ 种：

```python
from app.core.exceptions import ServiceException

raise ServiceException("用户名已存在")                          # ① 硬编码文案（不推荐，无法国际化）
raise ServiceException(message_code="repeat.submit.message")    # ② i18n key（推荐）
raise ServiceException.of(AuthErrorCode.USER_BLOCKED, username) # ③ 错误码枚举（推荐，见下）
```

第 ③ 种依赖错误码枚举携带 i18n key。以认证模块 `AuthErrorCode`（`app/api/v1/module_web/exception.py`，10000 段）为例，每个枚举值有 `.key` 属性指向消息：

```python
@unique
class AuthErrorCode(IntEnum):
    USER_PASSWORD_NOT_MATCH = 10005
    @property
    def key(self) -> str:
        return {AuthErrorCode.USER_PASSWORD_NOT_MATCH: "user.password.not.match", ...}[self]
```

`ServiceException.of(error_code, *args)` 把 `code`（int）、`message_code`（i18n key）、`args` 一起带上；异常的 `message` 是**惰性 property**，在全局异常处理器返回响应那一刻才按当前请求语言解析，因此翻译始终用对语言。

### 2.3 验证

`tests/test_i18n.py` 用 `use_locale` 上下文管理器成对 set/reset，覆盖了默认语言、回退、占位符格式化、未知 key 等场景，可直接参照写测试：

```python
def test_positional_args_formatted_zh():
    with use_locale("zh_CN"):
        assert MessageUtils.message("user.password.retry.limit.exceed", 3, 10) == "密码输入错误3次，帐户锁定10分钟"
```

## 3. 现状与边界（重要）

**i18n 机制与错误码体系已就绪，但业务消息只接入了一部分**——这与 README「业务消息逐步迁移中」的表述一致。写代码前先确认你要处理的消息属于哪一类。

### 已接入 i18n

| 位置 | 用法 |
|---|---|
| 认证模块（`module_web/auth`） | `ServiceException.of(AuthErrorCode.XXX)` + 登录日志流水 |
| 防重提交（`app/core/idempotent.py`） | `repeat.submit.message` |
| 限流（`app/core/rate_limiter.py`） | `rate.limiter.message` |
| 上传超限（`app/core/file_storage.py`） | `upload.exceed.maxSize` |

### 仍是硬编码中文（新增业务代码时可顺手迁移）

- **业务 CRUD 消息**：`module_system/`、`module_monitor/` 下大量 `raise ServiceException("中文文案")`；
- **响应封装默认消息**：`SuccessResponse(msg="操作成功")`、`ErrorResponse(msg="操作失败")`、`WarnResponse(msg="操作警告")`（`app/common/response.py`）——响应封装只是透传，翻译发生在调用方传入 msg 之前；
- **全局异常兜底文案**：`app/core/exceptions.py` 里"请求地址不存在"、"发生系统异常"等；
- **认证异常默认消息**：`NotLoginException` / `NotPermissionException` / `NotRoleException` 的默认文案（properties 里有对应词条 `not.login` / `not.permission` / `not.role`，但构造函数未走 message_code）。

> ⚠️ 消息文件里约一半 key 目前「有词条、无调用」（如 `sms.code.*`、`social.*`、部分 `*.length.valid`），是为后续迁移预留的。**词条齐全 ≠ 已接入**，判断是否生效要看代码里是否真的调用了 `MessageUtils.message` 或带 `message_code`。

## 4. 语言常量与扩展

后端**没有**专门的语言枚举，语言代码分散硬编码在三处：`app/utils/i18n.py` 的 ContextVar 默认值（`zh_CN`）、`app/core/middlewares.py` 的 `_resolve_locale` 映射、资源文件名约定 `messages_<locale>.properties`。

**新增一种语言**（如 `ja_JP`）需要同时：① 在 `_resolve_locale` 里加前缀映射；② 新建 `app/i18n/messages_ja_JP.properties` 并补齐全部 key。目前没有注册表式扩展点。

## 5. 前端侧（简述）

前端是**独立的另一套 i18n**（Vben Admin 的 `@vben/locales`，基于 vue-i18n），文案静态编译在 `apps/web-antd/src/locales/langs/{zh-CN,en-US}/*.json`，与后端 properties 互不相干。两者的唯一纽带是请求头：axios 拦截器把当前 UI 语言注入 `Accept-Language`：

```typescript
const language = preferences.app.locale.replace('-', '_');  // 'zh-CN' → 'zh_CN'
config.headers['Accept-Language'] = language;
config.headers['Content-Language'] = language;
```

因此：前端界面文案改前端 JSON，后端返回的消息（错误提示、业务消息）改后端 properties，切换 UI 语言时两边同步切换。
